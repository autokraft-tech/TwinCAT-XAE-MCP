# Existing nested ST Method validation

This change updates existing 609 Methods below one or more 601 folders in a 604 FB. Direct child creation and updates retain their existing behavior. Nested creation is not enabled.

Folder Methods require an exact startup-authorized Method path and type 609. A parent FB/root does not authorize them. The daemon checks the target, each actual COM Parent/PathName, the owning FB and the folders above it up to the configured POUs. Another FB, invalid node or mismatched path fails before mutation. ST language and full-content expectedHash remain mandatory.

Profile generation and lifecycle validation share read-only inspection of existing XAE-generated POU/FolderPath metadata. They refuse folder roots and nonexistent deep Methods. The runtime COM check remains authoritative. The profile helpers retain the existing NexPlc layout restriction and shallow creation scopes.

The save audit maps a Method to its actual owning FB file and selects its exact name plus FolderPath. Parent code, other Methods, folder metadata, GUIDs and Compile references remain protected. XML is inspected only; all engineering writes still use the typed XAE Automation Interface. Online operations and ALIAS remain disabled.

Offline verification on 2026-10-19: Release/x64 build; npm check/test/offline; daemon ping. Nested Method tests: 25 checks. Save audit: 76 checks including direct, one-folder and multiple-folder Method edits, GUID changes/invalid GUIDs, FolderPath changes, parent code and Compile-reference changes. Profile fixtures cover valid deep paths, missing Methods/folders, folder-only roots, traversal and wrong FBs. Fixtures do not establish real COM behavior.

Live evidence stays in ignored `artifacts/nested-method/`; profiles, PLC snapshots and journals must not be committed. The opt-in `tests/live-nested-method.js` performs read → set_impl → preview → audited save → audit → reload → readback → offline build → audited save → full Git diff, without retrying failed writes. It pins the existing SetManualMode target and separate acceptance/R23 worktrees.
